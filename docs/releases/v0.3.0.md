# PIIFlow v0.3.0 Release Notes

PIIFlow v0.3.0 adds policy-aware privacy-boundary evaluation on top of the
existing static taint analyzer. The feature set is frozen for this release:
source-code flow detection remains separate from policy decisions, and policy
fields are additive in text and JSON reports.

## Major Capabilities

- Static Python AST analysis without executing target applications.
- Structured taint propagation through bounded containers, attributes, aliases,
  helpers, imports, async handlers, and method calls.
- Sensitive-data classification for email, phone, medical, financial,
  government ID, and location signals.
- Sanitizer provenance on the actual propagation path.
- LLM sink provider and trust-zone metadata.
- YAML policy files with first-match `allow`, `deny`, and
  `require_sanitizer` actions.
- Reproducible original and policy benchmark runners.

## Benchmark Limitations

Benchmarks are synthetic, small, and project-specific. They do not validate
runtime behavior, legal compliance, production completeness, or performance
against CodeQL, Pysa, Semgrep, commercial tools, or other languages.

## Installation

From a checkout:

```bash
uv sync --extra dev
uv build
uv pip install dist/piiflow-0.3.0-py3-none-any.whl
```

## Quick Start

```bash
uv run piiflow scan examples/vulnerable_app
uv run piiflow scan examples/policy_apps/redacted_email.py --policy examples/policies/sanitized_email.yml
```

## Known Limitations

Known misses include closures, nested functions, dynamic attributes, dynamic sink
construction, exception-flow propagation, framework-generated values,
generators, and implicit/control-flow taint. Known false positives include
decorator-provided sanitization and runtime target checks that are outside the
static model.

## Upgrade Notes From v0.2.0

- Use `--policy policy.yml` to enable policy evaluation.
- Existing scans without `--policy` keep flow-detection behavior.
- JSON findings may include additional policy fields when a policy is supplied.
- Sink rules can now include `provider` and `trust_zone`; omitted metadata
  defaults to `generic` and `external`.
